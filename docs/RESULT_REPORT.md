# 결과 설명자료

제주 삼다수 취수원 지하수 Agent | 작성자: 황보민

## 1. 문제 정의
- 지하수는 제주의 주된 물 공급원이며, 제주도는 대표 관측정의 수위를 기준으로 단계별 제한 조치를 하는 관리제도를 운영함(2005 연구)
- 공개된 감시 데이터를 비전문가가 직접 읽고 해석하기 어려움
- 센서 값을 믿어도 되는지, 지금 평소보다 낮은지, 비가 안 오면 2주 뒤 어떻게 되는지를 말로 묻고 근거와 함께 답을 받는 Agent 구현
- 제조 공기업(제주개발공사)의 취수원 감시 센서 데이터에 설비 모니터링 방식(이상 유형 진단, 상태 진단, 예측)을 적용
- 주 사용자는 물 관리 담당자, 보조 사용자는 도민

### 전제
- 측정값 방향: 강수 뒤 값이 줄어드는 반응(상관 −0.36~−0.87)과 표선유역 연구(신문주 외, 2020)를 근거로 '물까지의 깊이'로 해석. 해석이 달라지면 `src/config.py`의 `VALUE_IS_DEPTH` 한 줄로 전환되도록 설계
- 기준 시점: 데이터가 2023-06-30까지이므로 '지금'은 그 시점 기준. 새 파일을 `data/raw`에 넣고 전처리부터 다시 실행하면 기준일이 따라감

## 2. Agent 구조
- 질문 입력, Claude API(claude-sonnet-5-5)의 도구 선택, 도구 실행(규칙·통계 코드), 결과 설명 순으로 동작
- 도구 7개: get_overview, get_status, get_forecast, get_sensor_events, get_values, get_rainfall, make_chart
- 한 질문에 도구 최대 8번, 데이터 밖 질문은 범위 밖으로 안내
- 분석 계산(이상 진단, 등급, 예측)은 규칙·통계 코드가 수행하며 LLM은 예측하지 않음
- 화면은 Streamlit(`streamlit run src/app.py`), 담당자·도민 모드와 '개발자 정보 보기' 체크박스(기본 꺼짐) 제공

## 4. 검증 방법
- 예측: 마지막 3개월(2023-04~06)을 떼어 두고 그 전 자료로 학습한 모델의 오차를 측정. 직전 값 유지와 비교하고 1수원 감시정3의 큰 변화 구간은 따로 집계. 미래 강수를 모르는 조건과 안다고 가정한 조건의 오차를 각각 계산
- 재현: 전처리, 센서 진단, 상태 진단, 예측 스크립트를 다시 실행해 결과 파일 8개의 해시가 이전과 같음을 확인. 새 폴더에서도 같은 결과 파일 5개의 해시가 일치
- Agent: 10문항을 실제 API로 실행하고 도구 결과와 답변을 대조. 답변 숫자는 도구 결과와 자동 대조하는 검사도 함께 사용

## 5. 향후 개선 방향
- 데이터가 2023-06-30까지이며, 새 파일을 `data/raw`에 넣고 전처리부터 다시 실행하면 기준일이 따라감
- 1수원 감시정3은 변화 폭이 커서 예측 신뢰도를 따로 표시함
- 예상 범위를 더 넓은 기간의 자료로 보정할 예정
- 실시간 센서 연결로 확장
- 등급은 18개월 관측 안의 상대 위치이므로, 지하수 관리제도의 기준수위와 대응시켜 공식 단계와 연계하는 방안 검토
- 수질·취수량 데이터를 추가하여 분석 범위 확대

## 6. 센터 활용 방안(제안)
1. 정기 점검 전에 "이상한 감시정 있으면 알려줘."로 점검 우선순위를 정하는 보조 도구로 활용(센서 이상은 '의심'이므로 현장 확인 병행)
2. 새 공개 파일을 `data/raw`에 넣고 전처리부터 다시 실행하여 기준일 갱신
3. 측정값 방향이 명세로 확정되면 `VALUE_IS_DEPTH`를 맞추고 결과를 재생성
4. 실시간 센서·기상 연결로 확장
